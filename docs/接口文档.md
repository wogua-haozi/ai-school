# 接口文档 —— report-server REST API

> 适用版本：2026-10（批39~43：请假四级+书记 / 学段隔离 / 报告分期 / 采购五级或签 / 班级记分 / 扬长七类 / 撤回普适 / 语音输入）。Base URL：本地开发 `http://localhost:8080`，容器化部署 `http://localhost`（web 容器 nginx 反代 `/api → server`）。交互式接口文档（Swagger UI）：容器 `http://localhost/swagger-ui.html`，本地 `http://localhost:8080/swagger-ui.html`。
>
> **覆盖说明**：本文档维护核心与早期模块的细粒度说明；2026-09 中旬以来新增模块（OA 审批五类 / 学生请假 / 门卫 / 通知中心 / 文明班与班级记分 / 扬长课程 / 邀请码注册 / 素材库 / AI 设置 / 系统参数等）以 **Swagger UI** 为准，关键端点见文末「新模块端点速览」。

## 认证与角色

**认证方式**：JWT Bearer。除 `POST /api/auth/login` 外，所有接口均需请求头 `Authorization: Bearer <token>`（OPTIONS 预检放行；无状态、无 session）。token 由登录接口返回，有效期 12 小时。

**角色与数据范围**（`DataScopeService.visibleClassIds` 一处收口，13 角色）：

| 角色 | 数据范围 |
|---|---|
| `ADMIN` 管理员 | 全校，不受数据范围限制 |
| `LEADER` 校领导 | 全校；设**分管学段**（小学部/初中部）后仅该学段 |
| `GRADE_LEADER` 级长 | 绑定年级（t_grade_binding，可多年级、同年级多人=德育/教学级长） |
| `DIRECTOR` 学成中心主任 | 全校；可另绑**级部主任**岗位（t_grade_binding duty=GRADE_DIRECTOR，请假一级审批与级长同权） |
| `DORM` 生活老师 | 全校（请假代录等行政线豁免） |
| `SECRETARY` 书记 | 全校（7~30 天请假终审） |
| `HEAD_TEACHER` 班主任 | 仅所带班级 |
| `TEACHER` 任课教师 | 仅任课班级（t_teach），所教科目外只读 |
| `PROCUREMENT` 招采 | 任课班级 + 物资核销出库工作台 |
| `LOGISTICS` 后勤中心 | 无班级数据面（批63 报修审批工作台） |
| `REPAIRER` 水电维修工 | 无班级数据面（批63 报修抢单工作台） |
| `PARENT` 家长 | 仅绑定孩子（requireBound） |
| `GUARD` 门卫 | 仅请假核验（JwtAuthFilter 白名单限 /api/student-leave + /api/auth + /api/app） |

下文"学生可见"= 该学生所在班级在当前用户可见班级列表内；"本班班主任"= ADMIN 或该班班主任（任课教师只读）。管理端 `/api/admin/**` 各组**全部仅 ADMIN**（部分页签放开有 ADMIN_ACCESS 的领导），组内不再逐条重复。

> **批51b 一人多岗（权限并集）**：GRADE_LEADER/HEAD_TEACHER/TEACHER/PROCUREMENT 的可见班级 = 任课班（t_teach）∪ 挂名班主任班（t_class.head_teacher_id）∪ 绑定年级班（t_grade_binding）；「该班班主任」一律按挂名认定（不问账号角色，checkClassOperable/请假代录/班级记分/请假详情同口径）。

## 统一响应结构

- 除下文明示"二进制"的文件端点外，统一返回 `ApiResponse<T>`：`{code:int, message:string, data:T}`
  - 成功：`code=0`、`message="ok"`、`data` 为业务数据（无数据时 `data=null`）
  - 失败：`code` 为业务错误码（400/401/403/404/500/502），HTTP 状态码与之一致，`message` 为可直接展示的中文提示
- 参数校验失败：HTTP 400，`message` 形如 `"字段名: 中文消息"`
- **401 行为**：未带/无效/过期 token 返回 HTTP 401 + `{code:401,message:"未登录或登录已过期"}`；登录接口密码错误同样 401。前端收到 401 一律清除 token 并跳转 `/login`
- 403：无权限（如"只有管理员或该班班主任可执行此操作"、"无权访问该学生（数据权限隔离）"）
- 429：登录防爆破——同一用户名连续失败触发锁定（Redis 计数，自动过期），锁定期内登录返回 429「失败次数过多，请 N 分钟后再试」
- **首登强制改密（mcp）**：管理员建号 / 重置密码 / 批量导入下发的账号首次登录后，token 携带待改密标记（JWT `mcp` claim），除 `login / me / PUT password` 三个接口外一律 403「请先修改初始密码后再操作」；改密成功换发新 token（标记清除）。存量旧账号不受影响
- 密码最短 **8 位**（建号 / 重置 / 自助改密全端一致）
- 二进制端点（`/api/report/file/*`、`/api/honor/file/*`、`/api/moment/file/*`、`/api/teacher-honor/file/*`、`/api/profile/photo/{userId}`、`/api/activity/{id}/cover`、`/api/admin/student/{id}/photo`、`/api/score/template`）不包 ApiResponse，直接返回文件字节流，**仍需带 Authorization 头**（iframe 无法带头，前端用 fetch 拉取 Blob）

## AuthController `/api/auth`

- `POST /api/auth/login` — 登录换 token（**公开**）
  - body：`username:String @NotBlank`、`password:String @NotBlank`
  - 返回：`{token, user{id,username,realName,role,perms[]}}`（密码错 401；停用账号 403）。**批49**：`perms` 权限点数组随登录下发（如 `SCORE_ALL`=全校成绩查看），前端入口门控用
- `GET /api/auth/me` — 当前登录用户信息。返回：`{id,username,realName,role,phone}`（**批53** 起带 `phone`，场地预约联系电话快照用；待改密态白名单，可访问）
- `PUT /api/auth/password` — 自助修改密码（登录态，待改密账号由此解除限制）。body：`oldPassword/newPassword:String @NotBlank`（新密码 ≥8 位；旧密码错 401）。返回：`{token}`——**新 token**，已清除待改密标记，旧 token 至自然过期前仍有效（批49 起响应含 `user.perms`）

- `GET /api/meta/subjects` — 学科列表。返回 `Subject[]`
- `GET /api/meta/my-classes` — 我的班级下拉，**按数据范围过滤**。返回 `[{id,name,gradeId}]`
- `GET /api/meta/all-classes` — **批56** 全校班级下拉（素养评价放开后数据面用）。全体教职工可用，家长 403

## StudentController `/api/student`

- `GET /api/student/list` — 学生选择（发起报告用），**按数据范围过滤，仅返回在读**（转出/毕业学生不参与日常业务；全量含历史届请用管理端 `/api/admin/student/list` 的 `status` 筛选）
  - 参数：`classId?`、`keyword?`（姓名模糊）、`page=1`、`size=20`（上限 100）
  - 返回：`{total, records[{id,studentNo,name,gender,classId,status}]}`
- `GET /api/student/{id}` — 单个学生基本信息（App 学生详情）。权限：学生可见
  - 返回：`{id,studentNo,name,gender,classId,status,guardianName,guardianPhone,dormBuilding,dormRoom,dormBed,editable}`
- `PUT /api/student/{id}/profile` — 订正学生资料。管理员/领导/该班班主任可改全部字段（body：`name?/gender?/studentNo?/guardianName?/guardianPhone?/dormBuilding?/dormRoom?/dormBed?`；**null=不动、空串=清空**）；**批60：生活老师（DORM）白名单只更新宿舍三列**，学籍/家长字段一律忽略（App 端「订正宿舍」入口）。返回 `{updated}`
- `GET /api/student/{id}/parents` — 该生家长账号列表（仅管理员/领导/该班班主任；生活老师 403）
- `GET /api/student/dorm/buildings` — 宿舍楼下拉（在读去重楼名）。全体教师（家长/门卫 403）
- `GET /api/student/dorm` — 宿舍查询（楼/房/床精确 + `q` 姓名学号；`page=1&size=50` 上限 100；返回 records 含 `className/guardianPhone`）。全体教师

## ScoreController `/api/score`（批63 口径：班主任/科任开**只读**入口——挂名班/任课班可看，无排名不可写不可导；其余普通角色仍 403）

**可见角色**：ADMIN、SECRETARY（书记）、GRADE_LEADER（级长，限绑定年级）、LEADER（校级领导，按分管学段）、`SCORE_ALL` 权限点（只读）、**批63 起 HEAD_TEACHER（挂名班）/TEACHER（任课班）只读**。名次两列与导出/全校汇总仅 canSeeRank 角色（ADMIN/SECRETARY/LEADER/GRADE_LEADER/SCORE_ALL），`listScores` 服务端置 null 收口；等级 `grade`（**批63c 起改校方上传制**：A~D 可带 +/-，存 t_score.grade；总分等级=subject_id NULL 行）随行对全部可见角色下发（家长端同口径）。现算机制（ScoreLevelService+score_grade_* 配置）保留为自治窗口不再驱动显示。**批75 走班分流**：`list`/`import-template`/`import`/`entry` 加 `walkClassId?` 参数——走班教师录自己走班的单科成绩（editable=canUploadWalk：ADMIN/书记恒真、走班教师考试开窗、级长开窗+本年级）；走班模板不带总分/等级列、导入外班学号整单拒；`class_rank` 对走班学科按 walkClassId 分组、非走班生按行政班（id+1,000,000 错开键空间防撞），行政班报表按学生归属聚合不动。

- `POST /api/score/exam` — 建考试（含科目与满分）。权限：ADMIN/SECRETARY/GRADE_LEADER。**批68 必选适用年级**
  - body：`termId:Long @NotNull`、`gradeId:Long @NotNull（批68：考试只作用于该年级；级长仅可建自己绑定年级，越权 403）`、`name:String @NotBlank`、`examDate:LocalDate @NotNull`、`subjects:[{subjectId:Long, fullScore:BigDecimal}] @NotEmpty`（科目不可重复）
  - 返回：`{examId}`
- `PUT /api/score/exam/{id}` — **批63 修改考试**（科目增删+各科满分）。权限：ADMIN/SECRETARY
  - body：`subjects:[{subjectId, fullScore}]`（整卷覆盖）；**删科连带删该科已录成绩**（前端二次确认）；降满分低于该科已录最高分 400
- `DELETE /api/score/exam/{id}` — 删整场考试。权限：**ADMIN/SECRETARY**
- `PUT /api/score/exam/{id}/entry-open` — 开关录入窗口。body：`open:Boolean`。权限：**ADMIN/SECRETARY**（关窗后 GRADE_LEADER 不可再录）
- `GET /api/score/exam/list` — 考试列表。权限：上述可见角色。返回 `[{id,termId,termName,name,gradeId,gradeName,examDate,classMaxTotal,gradeMaxTotal,subjectCount}]`。**批68 按数据域过滤**：GRADE_LEADER/HEAD_TEACHER/TEACHER 只见自己可见班级所在年级的考试+存量(gradeId=NULL)考试，管理面角色全量；绑定年级的考试跨年级 subject-context/list/import 一律 403
- `GET /api/score/subject-context` — 科目上下文。参数：`examId` + `classId`/`gradeId` **二选一**（批63 年级模式）
  - 返回：`[{subjectId,name,fullScore,classMax,gradeMax,editable}]`。editable 整卷化：ADMIN/SECRETARY 恒 true；GRADE_LEADER=录入窗口开；其余（LEADER/SCORE_ALL/班主任/科任）只读 false
- `GET /api/score/list` — 成绩单。参数：`examId`、`classId`/`gradeId` 二选一、`subjectId` **可空=总分模式**（批63：各科得分之和，不可录入，排名内存现算同分同名次）
  - 返回：`{fullScore, editable, gradeEditable, canSeeRank, rows[{studentId,studentNo,name,className,score,grade,classRank,gradeRank}]}`（缺分/未上传等级 null；无 rank 权限时名次服务端置 null；gradeEditable=等级上传通道开，总分模式也开——批63c）
- `GET /api/score/export` — 成绩单导出 xlsx（含名次列，gradeId 模式带班级列）。参数同 list。权限：**canSeeRank 角色**（班主任/科任 403）。**二进制**
- `PUT /api/score/entry` — 批量录入（score=null 清除；0≤score≤满分）。权限：**ADMIN/SECRETARY 全校；GRADE_LEADER 限绑定年级且录入窗口开放**。**批65 前端补删除口**：rows 传 `score:null + grade:null` 双空 = 删除该生该科整行（后端 writeRows 原有语义，教师端/管理端成绩页新增「删除」按钮直达）
  - body：`examId/subjectId:Long @NotNull`、`classId` **可空=年级模式**（批63：按 studentId 逐行校验，跨班一次保存）、`rows:[{studentId:Long, score:BigDecimal, grade?:String}]`
  - 返回：`{saved}`
- `PUT /api/score/entry-grade` — **批63c 等级录入（上传制，不动分数）**。权限同 entry。body：`examId @NotNull`、`subjectId **可空=总分等级**`（subject_id NULL、score NULL 行，不进排名）、`rows:[{studentId, grade}]`（grade 空=清除该行；格式 A~D 可带 +/-，归一 trim+大写，非法 400）
  - 返回：`{saved}`
- `POST /api/score/import` — Excel 导入（**单班多科**，列=考试科目+批63c 等级列）。权限同 entry。multipart：`examId`、`classId`、`file`
  - 批63 防呆：文件混入非本班学号→**整单拒绝**（message 列出学号，零写入）；单元格留空=不动该科/该等级；多余列忽略；**等级-only 单元格不误清已有分数**
  - 返回：`{saved, skipped[{studentNo,name,subject,reason}]}`
- `GET /api/score/template` — 下载导入模板（该班名册预填，列=学号/姓名/**[科目|科目等级]×n/总分等级**，批63c）。**二进制**
- `GET /api/leader/score-summary` — 全校/年级成绩汇总。权限：**canSeeRank 角色**（班主任/科任 403）。参数：`examId`。返回按班统计+年级排名
- `GET /api/leader/overview`、`GET /api/leader/teacher-usage?days=` — **批64 领导驾驶舱/教师使用情况**（登录/报告/评价/成绩/微光/AI 六类按师聚合，在职教职工含零活跃）。权限：**领导层（书记/领导/主任）+管理员**（级长/班主任/科任 403）；teacher-usage 管理端「教师使用情况」页签同源。**领导层定义（批64 拍板）：SECRETARY+LEADER+DIRECTOR 三角色，级长不算**；书记全面平权（报告任务读全量、账号审批、记分免排班、周报接收、checkClassOperable 全校），主任=驾驶舱+成绩只读（canSeeRank 放行、entry/upload 不放）

## RepairController `/api/repair`（批63 三层流转：审批后抢单）

状态机：`PENDING →（后勤中心审批）APPROVED →（任一维修工接单，条件 UPDATE 防双抢）CLAIMED →（接单人完成）DONE`；`PENDING/APPROVED → REJECTED（后勤拒绝）/ CANCELED（报修人撤回，未接单时）`。

**批63b 授权口径**：后勤中心/维修工 = `role` 为 LOGISTICS/REPAIRER **或** uid 在 `t_sys_config.repair_logistics_uids` / `repairer_uids` 白名单（逗号分隔，V47 种子=9 位报修人员的手机号教职工号，沿用原教师/主任角色）。登录与 `/api/auth/me` 响应下发 `repairRole`（LOGISTICS/REPAIRER/空）供前端工作台入口判断；REPAIR_TODO 通知按角色广播+白名单补发（去重）。

**批65 白名单自治**：`GET /api/admin/repair/whitelist` 读 / `PUT` 保存（body `{logisticsUids, repairerUids, ccUids}` 逗号串，回显保存后值）；仅 ADMIN，uid 逐个校验须为在职教职工（错号整单 400，防手滑）。管理端报修页签顶部「授权白名单」三组下拉自助维护，保存即生效（此前批63b 为 SQL 直配，学校改不了）。

**批67 B4 兜底删除**：`DELETE /api/admin/repair/{id}` 删已撤回的报修单（仅 ADMIN；仅 CANCELED 态，在办/办结单据留痕不可删 400；照片对象兜底再清防漏）。管理端报修页签 CANCELED 行「删除」按钮。

- `POST /api/repair` — 提交报修（全体教职工；家长 403）。multipart：`location`、`description`、`photos[]`（≤3 张）。返回 `{repairId}`；通知全体 LOGISTICS（REPAIR_TODO）
- `GET /api/repair/my?status=` — 我的报修
- `GET /api/repair/{id}` — 详情（报修人本人或管理员）
- `PUT /api/repair/{id}/cancel` — 撤回（发起人；PENDING/APPROVED 未接单时）
- `GET /api/repair/workbench` — 工作台（角色分流，其余 403）：LOGISTICS→`{todo[PENDING]}`；REPAIRER→`{open[APPROVED 抢单池], mine[本人 CLAIMED]}`
- `PUT /api/repair/{id}/approve` — 审批（仅 LOGISTICS）。body：`{approved:Boolean, note}`；通过→APPROVED 并通知全体 REPAIRER 抢单，拒绝→REJECTED 并通知报修人
- `PUT /api/repair/{id}/claim` — 接单（仅 REPAIRER，APPROVED 态；双抢后到者 400）。通知报修人
- `PUT /api/repair/{id}/complete` — 完成（接单人本人）。body：`{note}`；通知报修人 + 抄送 `t_sys_config.repair_cc_uids`（逗号分隔 uid）
- `GET /api/repair/file/{id}?idx=` — 凭证照片流（MinIO）。**二进制**

## AiController `/api/ai`（读=学生可见；生成/保存寄语=**ADMIN 或本班班主任**）

- `POST /api/ai/analysis` — 学业分析（规则引擎硬数字，不调大模型）。body：`studentId/termId:Long @NotNull`（无成绩 400）
  - 返回：`{advantage, toImprove, trend, alerts[]}`
- `POST /api/ai/comment-draft` — 班主任寄语草稿·**同步版**（AI 失败降级模板，存 t_comment.ai_draft）。body 同上
  - 返回：`{draft, source:llm|template, status}`。单发生成仍可用；页面已默认走下方任务队列
- `GET /api/ai/comment` — 寄语现状。参数：`studentId`、`termId`。返回 `{content, aiDraft, status}`（无记录 status="无"）
- `GET /api/ai/comment/export` — 寄语导出（班级×学期 → xlsx，含草稿与生效内容）。权限：**ADMIN 或该班班主任**。参数：`classId`、`termId`。**二进制**（文件名如 `寄语_初一(2)班_2025年秋季学期.xlsx`）
- `PUT /api/ai/comment` — 保存/确认寄语（confirm=true 才进报告）
  - body：`studentId/termId:Long @NotNull`、`content:String @NotNull`、`confirm:boolean`。返回同 GET
- `POST /api/ai/summary` — 成长总结草稿·**同步版**（不落库仅展示）。body 同 analysis
  - 返回：`{raw, blocks{本学期亮点,学习发展,综合素质发展,下一阶段建议}, source}`
- `POST /api/ai/tasks` — **任务队列·提交**（入队即返；切页/关浏览器后端照跑；同学生同类型未完成自动去重复用）
  - body：`type:String @NotNull`（`COMMENT`=寄语 / `SUMMARY`=总结）、`studentId/termId:Long @NotNull`。返回 `{taskId}`
- `GET /api/ai/tasks/{id}` — **任务队列·详情**（轮询取果）。权限：任务学生可见
  - 返回：`{taskId,type,studentId,termId,status(排队/生成中/成功/失败),source,error,createTime,startedTime,finishedTime, queuePosition?, result?}`——排队中附 `queuePosition`（前方第 N 位）；成功后 `result` 即同步接口的 data（COMMENT=`{draft,source,...}`，SUMMARY=`{raw,blocks,source}`）
- `GET /api/ai/tasks/mine` — **任务队列·我提交的近期任务**（全局任务面板数据源，含学生姓名）。参数：`limit=50`（上限 200）。按 `created_by` 过滤，**互相不可见**

**任务队列对接模式**：提交拿 taskId → 轮询 `mine`（前端 2s）驱动列表/进度 → 关心的任务转 `详情` 拿结果体。寄语结果另持久化于 `t_comment.ai_draft`（`GET /api/ai/comment` 可随时回显）；总结仅在任务 `result` 中。服务重启未完成任务自动重新入队。

## 大模型（AI）接入与模型切换指南

### 调用大模型的位置（共 3 处）

| 功能 | 入口 | 模型要求 |
|---|---|---|
| 班主任寄语草稿 | 寄语页「AI 生成草稿」/「本班全部生成」→ `POST /api/ai/tasks(type=COMMENT)` | 纯文本模型 |
| 成长总结四块 | 总结页「AI 分析该学生」→ `POST /api/ai/tasks(type=SUMMARY)` | 纯文本模型 |
| 荣誉证书图片识别 | 证书上传 `POST /api/honor/upload` | **必须多模态（vision）模型** |

协议为 **OpenAI 兼容 Chat Completions**（DeepSeek / 通义千问 / 智谱 / Kimi / OpenAI 均可）。AI 只组织语言，**全部数字与事实由规则引擎计算后注入提示词**，模型无法编造；寄语须教师确认后才进报告。

### 配置在哪、怎么换模型

**Docker 部署（推荐）**：编辑 `docker-compose.override.yml`（首次从 `docker-compose.override.yml.example` 复制），改完 `docker compose up -d report-server`：

```yaml
services:
  report-server:
    environment:
      AISCHOOL_AI_BASE_URL: https://api.deepseek.com   # 供应商 OpenAI 兼容地址
      AISCHOOL_AI_API_KEY: sk-你的key                  # 密钥只放本文件（已 gitignore，勿入库）
      AISCHOOL_AI_MODEL: deepseek-v4-flash             # ★ 换模型只改这一行
      # AISCHOOL_AI_CONCURRENCY: 16                    # 可选：任务并发（默认 16）
```

**本地开发**：改 `report-server/src/main/resources/application.yml` 的 `aischool.ai` 段（base-url / api-key / model / concurrency / timeout-seconds）。

| 环境变量 | 配置项 | 默认 | 说明 |
|---|---|---|---|
| `AISCHOOL_AI_BASE_URL` | aischool.ai.base-url | 空 | 留空 = 不启用 AI |
| `AISCHOOL_AI_API_KEY` | aischool.ai.api-key | 空 | 留空 = 不启用 AI |
| `AISCHOOL_AI_MODEL` | aischool.ai.model | 空 | 留空 = 不启用 AI；**三项须同时配置** |
| `AISCHOOL_AI_CONCURRENCY` | aischool.ai.concurrency | 16 | 任务队列 worker 数 = 对大模型的最大同时在途请求数 |
| — | aischool.ai.timeout-seconds | 120 | 单次 LLM 调用读超时，超时该条降级模板 |

**要同时用证书识别**：`AISCHOOL_AI_MODEL` 须配多模态模型（如 `deepseek-v4-flash-vision-exp` / `qwen-vl` / `glm-4v`）。

### 未配置 / 调用失败时的降级

- 三项配置留空 → 寄语/总结自动降级为**确定性规则模板**（硬数字仍准确），任务正常完成（source=template），前端有提示；证书转手动录入
- 单次调用失败/超时 → 同样降级模板，任务不报错；只有规则引擎本身异常（如无成绩）任务才置"失败"

### 供应商限额参考（DeepSeek 官方，2026-08 查证）

| 模型 | 并发上限/账号 | 超限行为 |
|---|---|---|
| deepseek-v4-flash | 2500 | HTTP 429（不封号） |
| deepseek-v4-pro | 500 | HTTP 429（不封号） |

默认并发 16 = flash 上限的 0.6%，多教师共用同一队列与 worker 池（并发不随教师数放大）；换限额更紧的供应商时按其限额调小 `AISCHOOL_AI_CONCURRENCY`。
