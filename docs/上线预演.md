## 二、上线顺序（关键：服务器先、APK 后）

App 页面全部来自服务器（WebView 即网页），**服务器部署完成 = 全体老师立即用上新功能，无需等 APK**。APK（19）只承载原生层：App 名称「石实SHINE」、官方校徽图标、启动屏、版本号（用于触发升级弹窗）。

1. **预检**：`bash deploy/backup.sh` 手动做一次上线前备份（MySQL + MinIO），确认备份文件落盘；
2. **服务器更新**——**本批起切换镜像化部署**（批44 已钉死 compose 顶层 `name: ai_school` 与镜像 tag，换目录不换数据卷）：
   ```bash
   # 本地（Windows，项目根）：
   docker compose build server web
   docker save aischool/report-server:1.0 aischool/report-web:1.0 | gzip > local/imgs.tgz
   python local/scp_push.py local/imgs.tgz        # 推到服务器
   # 服务器（项目目录）：
   docker load -i imgs.tgz
   docker compose -f docker-compose.yml -f docker-compose.server.yml -f docker-compose.override.yml up -d   # 不带 --build
   ```
   好处：服务器不再现场构建（国内源拉依赖慢/不稳），镜像与本地验证过的完全一致。
   **⚠ 10-10 首测实录：镜像包传输被链路切断**——1.95GB tgz 经 SFTP put 与 exec 管道流均在 0 字节即断（ENOENT / Socket closed；小流量 exec/裸命令全程正常，10MB 也断，非配额非磁盘，疑似链路层对 SSH 内持续大流量的 DPI 干扰）。小文件经「先 sftp.stat(父目录) 再 put」模式可过（原因未明但可复用）。本次回退老链 `git pull + up -d --build` 部署成功（服务器层缓存热，增量构建快）。下次部署先试 stat→put 传大包；学校新服务器到位后重新首测。
   **⚠ 三个 `-f` 一个都不能少**：服务器上没有 .env，生产数据库/MinIO 密码全在 `docker-compose.override.yml`。9-26 事故实录：漏掉第三个 `-f` 重建 web，compose 检测到配置漂移把 mysql/server/minio 一并按错配置级联重建，server 连库 Access denied 崩溃循环（数据卷无损，按完整命令重跑即恢复）。
   回退方式：镜像链故障时仍可走旧链 `git pull && docker compose -f ... up -d --build`（服务器自行构建）。
3. **服务器验证**：`docker compose ps` 五容器 healthy；浏览器登录管理端跑一遍数据体检；`/api/app/latest` 仍返回 code 21（APK 未发前不应变）；
4. **发 APK**：`python local/pub_release.py local/release/shishi-growth-v1.2.2.apk 1.2.2 23 "更新说明逐行"` → 老师 App 自动弹升级，App 内下载安装（**发前先问用户**）；
   **⚠ 打包必须用 `bash local/build_apk.sh`，不要手工拼 vite build + cap sync + assembleRelease**——9-26 事故实录：手工打包漏注入 `CAP_SERVER_URL` → APK 19 无 `server.url`、dist 也不完整 = 死壳（页面能渲染、所有请求发往不存在的本地地址、服务器日志零请求、且 App 内升级通道也死），已装设备只能浏览器/微信手动装 1.1.1（code 20）。build_apk.sh 自带防呆：sync 后校验 capacitor.config.json 含 server.url，否则直接构建失败。本批 APK 23 需重打（MainActivity 原生 insets 兜底为唯一原生层增量）。
5. **发后验证**：`/api/app/latest` 返回 code 23；平板真机开 App 验证返回键不再被状态栏遮挡（批46②）。

**服务器回滚**（页面立即回到旧版，优先执行）：

```bash
cd <服务器项目目录>
git checkout <旧版commit>          # 上线前记下 git rev-parse HEAD
docker compose -f docker-compose.yml -f docker-compose.server.yml -f docker-compose.override.yml up -d --build
```

- 数据层无需回滚：本批 V32-V39 全部为加表/加列（V38 班级记分表、V39 采购明细表），旧代码不读新表新列，新 schema 跑旧镜像安全；
- 回滚后旧 APK（21）与新 APK（22）均可用——App 页面来自服务器，壳版本不影响。

**APK 侧处置**：

- 升级弹窗有问题：管理端「版本更新」页签点**撤回**，未升级的老师不再提示；

**回滚后动作**：保留现场（容器日志 `docker compose logs --since 30m` 存档）、通知用户、定位修复后重新走上线流程。
